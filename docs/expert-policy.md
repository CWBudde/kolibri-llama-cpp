# Expert cache policies, replayed online

Generated by `go run ./cmd/kolibri-policy -models Kolibri-1-IQ3_XXS-IQ4_XS-down-imx,Kolibri-1-Q8_0 -md docs/expert-policy.md` from the selection files of `tools/locality/experts.py`, the answers in `testdata/locality/<workload>.json` and the expert sizes in `testdata/locality/expert-bytes.json`; do not edit by hand.

The workloads are replayed in the order an online server with a prompt cache meets them: each prompt's new tokens prefilled in ubatches, each answer decoded token by token. A decoded token needs its six experts per layer; a prefill ubatch the union of its tokens' experts, once. The policy learns a step's experts only when the step runs (PLAN Phase 10, Stage A). An answer that stopped at the token limit decodes all but its last token, which the next prompt's prefill processes.

Prefill and decode are counted apart: a prefill hit serves a ubatch of up to hundreds of teacher-forced tokens at once and is no decode speedup. MB/token are the expert bytes a phase's misses load per token of that phase. The trace-order hit rate replays every token as one decode step, the order of [expert-cache.md](expert-cache.md), whose hits it reproduces exactly.

Policy: an LRU cache of the given number of experts in every layer, the only policy so far. Cache GB counts the expert bytes it holds when full.
